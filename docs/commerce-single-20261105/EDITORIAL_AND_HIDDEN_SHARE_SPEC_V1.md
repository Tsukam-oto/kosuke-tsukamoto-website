# 特設サイト｜文章の再設計と縦8文字の共有機能
2026-11-16 / 編集・UX仕様。**本番サイト未変更。本人未承認の制作ノート8行は公開しない。**

## 方向修正（本人の最新の評価を最優先）
これまで作成した「けっこんしました」8行の文章は、本人が「内容がおかしい」「何について書くのか不明瞭」と判断した。使える原稿として扱わない。「あのとき」「肩を叩く手」「救われた」等を機械的に並べたものを公開しない。歌詞の要約を寄せ集めて作る方針は中止。

## 文章の担当を分離する
1. **作品全体の紹介**：なぜ配信を始めるか（身近な人に届ける音楽→学校現場が創作の中心→卒業・異動による別れ→距離を越えて届く形にしたい）。なぜ《あなたと》《これから》が大切か（各年度の卒業生と一緒に作った作品だから）。学校から音楽活動が移動するわけではない。意図しない商業・成功・音楽活動宣言の話にしない。
2. **各曲の紹介**：《あなたと》《これから》で別々の歌詞・制作経験を説明。《これからも》は自分のこれからを喜んだ人がいたこと、人の温かさと煩わしさ、忘れる／思い出す、一人で書いていても一人ではないこと、変わっていく風景の中で音楽を続けていくことを候補として整理。ただしすべてを1曲の解説へ機械的に詰め込まない。
3. **《これからも》の制作ノート／秘密の8行**：自然に読める1本の文章として成立することを前提とする。縦読みのために題材のない随筆を捏造しない。縦読み「けっこんしました」は説明・見出し・色付けをせず、本人が公開承認するまで実装・表示しない。縦読みは歌詞に新しい文字を加える行為ではなく**ウェブ上の制作ノートの仕掛け**。

## 既存サイトの共有機能（GitHub main/index.htmlで確認）
- `#lyric-share`：LYRIC BOX の2つの歌詞断片を、`openShare({lines, source, anchor})` に渡してシェアモーダルへ。
- 歌詞全体の `.poem-share-begin`：任意の `.poem-line` をクリックで選択 → `#phrase-share` → 同じ `openShare`。
- シェアモーダル `#share-modal`：テキストコピー、X、LINE、Web Share API、Instagram用画像（4:5 / 9:16）の作成、PNG保存。
- **重要**：`openShare` はホーム `index.html` の `DOMContentLoaded` クロージャ内にあり、特設サイト別HTMLからは直接呼べない。共有UIの見た目とpayload形式を再利用するには、破壊的な共通関数化を避けて専用の独立モジュールへ切り出す、または特設ページで同等のUIを局所実装する。

## 新しいインタラクション：縦列だけを1つの選択対象にする
- 8行は普通の横書き文章。各行**8文字目のみを同じx座標に揃える**。8文字目を縦に読むと「けっこんしました」。
- 通常時は他の文字と同色・同じウェイト。初めから秘密を派手に示さない。
- PC：8文字目の列をマウスでホバーすると、その**列だけ**が微細に反応（薄い下線・背景等）。スマホ：縦列の領域をタップすると選択状態へ。ブラウザーの通常のテキストドラッグ選択に頼らない。
- **一度の操作で縦8文字をまとめて選択**。8回タップさせない。選択後は「この言葉をシェアする」操作を示す。
- 選択後だけ `けっこんしました` を共有payloadのlines[0]にして、既存のWORDS共有画面と同じコピー／投稿画像生成へ。公開URLは本物の特設ページアンカーへ。
- 自動投稿はしない。コピー・共有するかどうかは閲覧者が判断する。
- キーボードでも操作可能な単一のbutton要素として実装。フォーカスの視認性、閉じる動作、Esc、スクリーンリーダーのラベルを用意。
- 8文字の見た目の列をクリック対象として使うが、**文章全体の横書き読解・テキストコピーを阻害しない**。スマホで7文字のprefixが折り返されないように固定幅、残りはtailに折返しを許可する。
- 選択時のみ隠しメッセージを見せる。URL直接アクセスでは「けっこんしました」を見出しにしない。
- 必ずスマホ375px〜のタップ領域と縦の列の一致を実機確認する。ARIA・ズーム200%の読みやすさも確認。
