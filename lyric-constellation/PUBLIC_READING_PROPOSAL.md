# 歌詞の星座｜公開版と読解品質の設計提案（草案）

> **現段階では公開を承認したことにはなりません。** 本文・未発表作品・作者メモ・下書きの公開は行わない。公開サイトの動作変更もこの提案書には含めない。

## 1. 目的と読む人の体験

「作品の星が168個ある」ことではなく、**一つの言葉や作品を起点に、別の作品の見え方まで変わる読書体験**を提供する。

閲覧者が選ぶ入口は3つ。
- **一曲から読む**：原文（公開可能な範囲）→その曲の読み→対照になる別作品→別の読み方。
- **一つの言葉から読む**：出典を確認した共通の一行／語の変奏のみをたどる。似た意味であるとは自動的に断定しない。
- **一つの星座から読む**：編集した道筋（初期は5〜8本程度を候補とする）を2〜4作品程度のまとまりでたどる。

大きな星図は発見を支える視覚表現。主役は必ず原文と読解。モバイルでの読みやすさを優先する。

## 2. 非公開の正本と公開版の境界

- **正本**：既存の本人専用168作品、版管理された歌詞原文、個別精読、作品間比較、星座、作者の既存メモ。現在の本人限定認証とRLSを維持する。
- **公開版**：別個の編集済み・明示的な公開許可範囲だけを含む静的データ。閲覧者から本人専用テーブルへアクセスさせない。本人用データのRLSを緩めない。
- **公開候補**：すでに正式に一般公開されている原文や、別途公開範囲の決まった短い引用を優先する。「データが精読済み＝公開してよい」ではない。
- **除外**：未発表原文、言葉の地層、余白の下書き、非公開エッセイ、作者メモ、保存した判定、個人情報、本人認証情報。
- 作品名・別名義との結び付きも公開対象の一部として扱う。公開範囲の決定前に、名義の関連を新たに外部へ示さない。
- **作者に168件の一つずつのチェックを要求しない。** 公開時に必要なのは、一度の明確な公開範囲の意思決定であり、日常の読解の承認ではない。

### 推奨アーキテクチャ

`非公開正本 → 出典・版番号の照合 → 編集候補 → 自動品質検査 → 公開許可済み素材のみ抽出 → 公開用の独立した静的JSON → 読書画面`

CI・ログ・PR・プレビュー・テストフィクスチャへ非公開原文をコピーしない。公開データの作成前に許可リストで対象を確定する。未指定作品はデフォルト拒否。プレビューURLも公開扱いで取り扱う。

## 3. 読解の品質基準（公開の前提）

公開候補の文章は次の条件をすべて満たす。AIが量産した比較をそのまま公開しない。

1. **正しい出典**：使用した引用が保存された原文の指定版に完全一致。作品ID・原文版・引用位置を内部的にたどれる。歌詞の捏造・誤引用0件。
2. **解釈と観察の分離**：「原文にあること」と「こう読めるという仮説」を分け、作者の制作意図や経験を断定しない。
3. **二作品の根拠**：関係を述べるなら双方の作品に根拠があること。「希望」「成長」など一般語だけの結び付けを採用しない。
4. **差異まで読む**：似ているだけでなく、視点・時制・意味・態度・語りの相違、または別の読み方を示す。反証的に読む余地がある場合は併記する。
5. **読書として成立**：初見でも「なぜ隣の曲へ移ったか」が理解できる。星の数、比較件数、作者確認済み件数を品質や価値の代替指標にしない。
6. **公開権限**：本文・引用・名義・作品名を含む表示素材が公開許可範囲内。対象外素材の公開件数0件。
7. **アクセシビリティ／操作**：390px程度のスマートフォンでもスクロールやタップが困難にならず、キーボードでも辿れる。ログインしていない状態でも公開版だけで成立する。

**品質の測り方**は読解の「点数」ではなく、原文照合・欠落・出典・非公開漏出に関する必須合否と、編集上の弱点（表層一致／飛躍／反証不足／繰り返し）を記録する。

## 4. 公開サイトの情報設計

- 冒頭：短い紹介文＋「一曲から」「言葉から」「星座から」の3入口。
- 読書画面：①入口の作品と原文の許可済み引用 ②精読の核となる問い ③次の作品とその引用 ④どこが同じで何が違うか ⑤別の読み。
- 星図：選択作品の周囲だけを優先表示し、全体星図は補助的に展開可能にする。
- 作品紹介の末尾に、公開済み音源・作品ページへの導線を置けるようにする（実際にURLが存在するものだけ）。
- 読者の反応や作者の一件ずつの認証を公開条件にしない。
- 公開版のキャッシュを分離し、プライベートAPI・個人メモ・下書きのキャッシュを絶対に混在させない。

## 5. 進行順（公開を急がない）

**Phase A｜非公開で読解の地固め**
- 168作品それぞれの原文版・個別精読の網羅状況を可視化する（作者ではなく管理側の作業）。
- 引用の一致を機械的に検証し、比較の根拠不足・重複・解釈の飛躍を洗い出す。
- 作品単位の精読を先に深め、作品間比較は根拠に沿って追加・修正する。

**Phase B｜公開前の編集版**
- 質の高い少数の星座を、読者がたどれる短い文章に編集する。
- 公開候補を**すでに公開済みの素材**から選び、匿名閲覧の静的データだけを対象に検証する。
- 実名と木乃伊名義のつながりを含む公開範囲は、必要な時点に一度だけ明示的に確認する。本人の個別読解承認は求めない。

**Phase C｜公開判断**
- 必須品質チェックがすべて合格し、公開範囲への明示的同意が得られた時点で公開作業。
- 公開後も本人専用正本と公開スナップショットを分離したまま改訂する。
- 公開中止・差替え時にすぐ非公開化できる手順とキャッシュ更新も整備する。

## 6. 現行実装との整合

2026-11-06時点の公開アプリでは、非公開の木乃伊原文はログイン後に `lyric_master_works` と `lyric_master_text_versions` から取得し、作品間比較は `lyric_cross_readings`、星座は `lyric_close_reading_paths` から本人用に読み込む仕組み。公開用の作品とは混同しない。PR #63までに作者の判定は必須ではなくなった。この提案書ではDB、サイト、原文の変更は行わない。

## 7. 将来の改修の受入条件

- サイト機能の追加がなくても、読解の誤りが減り、作品への理解が具体的に深まること。
- 公開候補で原文照合不一致＝0、公開禁止素材の混入＝0。
- 未ログイン者が本人専用データを取得できないことを自動・実ブラウザの双方で検証。
- 「AIの読解仮説」「原文の根拠」「作者が実際に書いたこと」が混同されない。
- **作者に新たな確認作業・採点・チェックを課さないこと。**
